## How to write this

**Purpose:** docs are practical, not persuasive. Someone lands here to *use* the feature. Get them there fast.

**Before writing:** read an existing doc in the same area and match its style, depth, and formatting. Consistency beats creativity in docs.

**What to include:**
- What the feature does — one concrete paragraph
- When to use it — describe the *situation*, not the capability ("When your team needs to…" not "This feature enables…")
- How to get started — numbered, specific steps
- Prerequisites or requirements — if any

**What to skip:** marketing language, exhaustive configuration (cover the 80% case, link the rest), screenshots that will go stale, and anything that just repeats the marketing site.

**Tone:** helpful and direct, like a good README. Just clarity.

**Cross-reference:** link to and from related docs; update the getting-started guide, FAQ, or overview if this touches them.
