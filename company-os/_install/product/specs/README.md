# Specs

A spec here is a **paste-ready** brief for one buildable piece of work — tight enough to drop straight into Linear, Notion, or wherever the team tracks work, with no reformatting.

## How this works

- **Copy `_template.md`** into a new file per spec — kebab-case, named for what ships (`inline-comment-threads.md`, not `notes-from-standup.md`).
- **Drafts live here first.** Once a spec is scoped and ready to build, paste it into the tracker; leave the file here as the source of record and link the tracker issue back into it.
- **Specs stay tight.** Problem, audience, success criteria, an optional solution sketch, open questions, GTM notes — nothing else. If a section balloons, the extra belongs elsewhere: a strategy claim goes to `../strategy/`, an unresolved question goes to `../discovery/`, raw user signal goes to `../user-feedback/`.
- **A spec is downstream of input, not the input itself.** It should trace back to a painpoint, a discovery finding, or a strategy thesis — link to that source rather than re-deriving it.
