# Playbooks

**How we think about a domain** — the team's shared reasoning, not step-by-step checklists. Load the relevant playbook before doing that kind of work, so the approach is consistent no matter who (or which agent) is doing it.

Playbooks are *philosophy + approach*; the mechanical "do X then Y" belongs in a process doc or a command. A playbook earns its place once the team has a real point of view on the domain.

## What's here

| Playbook | When to load it |
|---|---|
| `sales.md` | Any sales or outreach work |
| `content.md` | Writing or planning content |
| `launch.md` | Shipping or announcing something |

Add a playbook when you notice you keep re-explaining "how we approach X". Name it `<domain>.md`.
