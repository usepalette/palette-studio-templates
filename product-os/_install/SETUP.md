This workspace was created from the **Product OS** template. An agent can complete most of this
with `/onboard`, or when the user says "set me up."

Setup adapts to the team. A solo user is valid. A team without a formal product owner, issue
tracker, analytics tool, CRM, or existing feedback is valid. Mark an item complete when the team
has configured it or deliberately recorded `not used`.

## Steps

- [ ] **Scope and basics** - product, product area, platform, or portfolio scope; name; one-line
      description; users; and current surface captured in `documentation/product-overview.md` and
      the root README.
- [ ] **Prefill source chosen** - a live connector, documents in `_inbox/`, exported context, or
      manual setup. Starting with no existing context is allowed.
- [ ] **Responsibility and attribution separated** - the workspace steward is recorded as the
      owner, and `last_updated_by` names the current human who performed setup.
- [ ] **Working shape chosen** - relevant teammates and modules are configured; optional profiles,
      folders, and integrations are either kept for later or deliberately skipped.
- [ ] **Feedback path recorded** - existing sources are linked, or manual `/feedback` capture is
      recorded as the starting workflow.
- [ ] **Live systems recorded** - the issue tracker, analytics, and other tools are linked when
      used; otherwise their value is explicitly `not used`.
- [ ] **Next workflow chosen** - the user knows whether to start with feedback, synthesis,
      discovery, strategy, or a spec. Existing product data is not required to finish setup.

## When complete

Set **Status: COMPLETE**, offer to delete this file, and work normally. Keep it if the team wants
the setup record. Use `/finish-session` after meaningful work and `/workspace-heal` weekly.
