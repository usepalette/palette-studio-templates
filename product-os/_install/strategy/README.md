# Strategy

Durable product strategy theses: claims about how the product wins, not a list of what ships next.

## What belongs here

A strategy file should outlive one planning window. It connects evidence from user feedback,
discovery, competitors, analytics, and team input to a claim about positioning, moat, or
sequencing.

Specific builds belong in `../specs/` and, when used, the issue tracker. Open questions belong in
`../discovery/`.

## How to work

- Start from `_template.md`.
- Name files for the thesis, not the meeting where it arose.
- Include counter-arguments. A thesis without a credible counter is advocacy, not strategy.
- Link upstream evidence and downstream implications.
- When the thesis changes materially, keep a revision note instead of rewriting the history away.
